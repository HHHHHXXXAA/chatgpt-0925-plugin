# 0925-DEV v2.6.6 唯一运行合同

## 用户流程

严格执行五步：

1. 展示固定五类目：1 保健营养、2 母婴、3 个护清洁、4 美妆护肤、5 食品营养食品；等待选择。
2. 选择后等待本次当前 Excel；没有当前 Excel 不读取历史附件、不开始分析。
3. 收到 Excel 后完成一次连续深读，聊天只展示可执行的方图结果；通过后等待“确认出方案”。
4. 收到“确认出方案”后，按所选类目框架填写 A/B/C/D 四套完整方案；等待“开始生成”。
5. 收到“开始生成”后，A、B、C、D 四次独立单画布事务，交付四张独立方图。

不得增加逐图确认、重复上传、逐图授权或让用户补做内部整理的步骤。

## 事实边界

- 当前 Excel 的方图框内内容是最终展示事实源：文字、产品、Logo、人物、截图、组件、结构和底部内容均按对象来源读取。
- 指向方图的框外说明是执行指令，必须绑定到目标对象或区域；框外说明本身不自动成为广告文案。
- 方图框外未指向方图的内容、长图主体和长图底部全部排除，绝不能进入最终方图。
- 当前用户要求优先于框架示例和历史规则；框架示例、历史商品和历史 Excel 不得补全事实。
- 只有真实不确定的对象、边界或修改冲突才提出选项；普通设计选择由插件内部解决。

## 深读范围与对外输出

内部必须完成工作簿、工作表、合并区、公式显示值、富文本、批注、文本框、绘图锚点、嵌入媒体、DISPIMG、截图文字与设计结构的读取和实际视觉核验。内部记录对象来源、用途、方图边界、长图排除区、COPY_LEDGER、素材来源、截图合同和 BOTTOM_CONTRACT。

聊天对外只展示：

1. 当前工单、选择的类目框架和读取状态；
2. 方图框内全部正式文案，逐字保留数字、标点、换行、分组和顺序；
3. 产品、Logo、代言人/模特、签名、截图和参考图的实际选用来源；
4. 每条框外标注的“原文 → 目标对象/区域 → 执行动作”；
5. 截图需保留、重建、排除的文字、组件、结构和范围；
6. 方图底部固定合同，包含文案、分组、行序、换行、字号比例、字色、坐标、宽度比例、对齐和贴底关系；另列长图底部排除；
7. 锁定项、可变项和真正未解决项；
8. 结果只收尾为 `READY_FOR_PLAN` 或具体 `BLOCKED_PARSE`。

不要展示无关表格、解析日志、哈希清单、重复门禁清单、历史规则复述、营销推断或“待完成内部检查”。证据不足必须阻断，不能用“按 Excel 执行”代替证据。

## 锁定与可变

绝对锁定：

- 产品/包装原图的身份、标签、比例、颜色和文字；
- 品牌 Logo、店铺 Logo、签名的原图身份；
- 正式文案 COPY_LEDGER，禁止删改、截短、换写、补写；
- 代言人原图、身份、脸、服装、姿势、手势、朝向和手持关系；
- 截图中明确需要展示的正式文字、数字、组件关系和结构；
- 方图底部文案、分组、行序、换行、字号比例、字色、坐标、宽度比例、对齐和贴底关系。

允许变化：

- 非底部区域的场景、背景、光线、材质、视角、构图骨架、视觉动线和信息容器；
- 普通模特仅在当前 Excel 或框外说明明确要求时变化；没有模特要求不得添加人物；
- 底部文字框的外观皮肤、填色、圆角、切角、描边和阴影；不得改变固定文字几何、颜色规则、文字和层级。

## 五类目框架

读取 `references/prompt-frameworks/` 中与选择对应的原始框架和 `使用说明_填写清单.txt`。框架只提供字段顺序和类目视觉方向；每个字段使用当前 Excel 事实，缺失字段写“不适用/未提供”，不得使用框架示例补事实。

方案阶段每套必须填入：方案定位、画布成品要求、受保护素材、正式文案、构图骨架、产品表现、标题与主信息、卖点组织、Logo/截图位置、背景与色彩、光影与材质、底部合同、模特规则、禁止事项、最终成品检查点和本套单画布提示词。不得写“同上”“沿用前文”“按 Excel”。

## 四套差异合同

- A：更多参考当前 Excel 参考图的设计形式、空间关系和信息层级。
- B：与 A 不同的商业视觉系统、构图骨架、主体比例和信息呈现。
- C：与 A/B 不同的模块化或专业信息结构、镜头语言、光线和材质。
- D：与 A/B/C 不同的生活方式或情绪场景、视角、色彩角色和留白关系。

四套至少在构图、主体占比、视角/景别、场景、光线、材质、留白、动线、信息模块和主色角色中形成明显差异；不能只换背景色、滤镜、装饰或轻微移动。差异不得改变任何锁定事实。

## 生图与交付

每次只处理一个活动方案和一张 1:1 画布；调用上下文不能出现四宫格、拼贴、联系表或多方案集合指令。实际生成前绑定当前 Excel 源图、COPY_LEDGER、SCREENSHOT_STRUCTURE_CONTRACT 和 BOTTOM_CONTRACT；无法绑定真实源素材时阻断。

背景只是内部环境；必须继续合成原产品、Logo、人物、截图有效组件、逐字文案和固定底部，不能交付无字背景、模板或中间图。展示前拒绝拼接、多画布和缺少完整文案的结果。

最终只有四张独立文件全部通过产品/Logo/文案/截图/人物/底部/差异/商业质量检查后，状态才是 `DELIVERABLE`；数量不足、事实错误或视觉差异不足时为 `REJECTED_QA` 或 `BLOCKED_*`，不得静默降级。
